# Reports contract

`contracts/reports` stores reports and disputes on NEAR. Report submissions and disputes require at least `REPORT_DEPOSIT` yoctoNEAR. Deposits are never refunded in any report or dispute state. Reports and dispute rows are permanent: state changes update them in place, and the contract has no row deletion or refund method. `Report` stores accepted-chain links (`accepted_prev`, `accepted_next`) and deny-chain links (`deny_prev`, `deny_next`). `report_and_dispute_storage_measurement_is_pinned` measures 1,927 bytes for one maximum-size report through acceptance and 734 bytes for one maximum-size dispute and pins both numbers exactly. `REPORT_DEPOSIT` is the larger measurement with a 20 percent margin, `23124000000000000000000` yoctoNEAR (`0.023124` NEAR), and the test pins it equal to that amount. The sandbox test proves both deposits remain in the contract account after overturn.

`subject` means **the account agents should not pay; never a victim**.

The canonical report body behind `body_sha256` has exactly the fields `evidence_sha256`, `evidence_url`, `kind`, `outcome`, `subject`, and `submitter`. Serialize them as UTF-8 compact JSON with keys in that sorted order, no spaces, and no null fields, then hash those bytes with SHA-256. `fixtures/records/body-vector.json` is the shared Rust and Python test vector.

Kinds, outcomes, and states serialize as the lowercase values in `intel/record_enums.json`. `rust_enum_values_match_the_canonical_json` compares the contract enums to that file.

The only report state changes are pending to accepted or rejected by a moderator, pending to withdrawn by the submitter, accepted to contested by a dispute, and contested to accepted or overturned by a moderator. `all_disallowed_report_state_transitions_are_refused` exercises every other transition from every non-pending state; the method tests above prove each allowed transition. Rows remain stored through every transition.

The `shieldbot-near` 1.0.0 NEP-297 events are `moderators_updated`, `report_submitted`, `report_moderated`, `report_withdrawn`, `report_disputed`, and `dispute_resolved`. The moderator update contains the new moderator list. Report events include the report id, subject, state, and report body hash; dispute events also include the dispute id. `owner_can_set_moderators` and `emits_all_five_nep_297_events_with_report_identity` prove these event fields.
