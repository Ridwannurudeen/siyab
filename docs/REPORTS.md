# Reports contract

`contracts/reports` stores reports and disputes on NEAR. `submit_report` and `dispute` require exactly `REPORT_DEPOSIT` yoctoNEAR; any other amount is refused with `REFUSED:bad_deposit`. These deposits are a non-refundable storage fee that stays in the contract account in every state. `withdraw` returns nothing, and no method returns a report or dispute deposit. Report and dispute rows are permanent: state changes update them in place, and the contract has no row deletion or refund method. `Report` stores accepted-chain links (`accepted_prev`, `accepted_next`), deny-chain links (`deny_prev`, `deny_next`), and `upheld_disputes`, a statistic of disputes resolved against the disputer, saturating at 255; no rule reads it. `report_and_dispute_storage_measurement_is_pinned` measures 2,046 bytes for one maximum-size report through acceptance and 734 bytes for one maximum-size dispute and pins both exactly; `REPORT_DEPOSIT` is the larger measurement with a 20 percent margin, `24552000000000000000000` yoctoNEAR (`0.024552` NEAR), and the test pins it equal to that amount. `new` and `set_moderators` refuse a moderator list that names the same account twice (`REFUSED:duplicate_moderator`), so the single moderator exception counts distinct accounts. The sandbox test proves the report and dispute deposits remain in the contract account after overturn.

`subject` means **the account agents should not pay; never a victim**.

The canonical report body behind `body_sha256` has exactly the fields `evidence_sha256`, `evidence_url`, `kind`, `outcome`, `subject`, and `submitter`. Serialize them as UTF-8 compact JSON with keys in that sorted order, no spaces, and no null fields, then hash those bytes with SHA-256. `fixtures/records/body-vector.json` is the shared Rust and Python test vector.

Kinds, outcomes, and states serialize as the lowercase values in `intel/record_enums.json`. `rust_enum_values_match_the_canonical_json` compares the contract enums to that file. `deny_follows_kind_alone_for_every_outcome_when_accepted_and_contested` checks all 24 kind/outcome pairs in both accepted and contested states.

The only report state changes are pending to accepted or rejected by a moderator, pending to withdrawn by the submitter, accepted to contested by a dispute, and contested to accepted or overturned by a moderator. `all_disallowed_report_state_transitions_are_refused` exercises every other transition from every non-pending state; the method tests above prove each allowed transition. Rows remain stored through every transition.

The `shieldbot-near` 1.0.0 NEP-297 events are `moderators_updated`, `report_submitted`, `report_moderated`, `report_withdrawn`, `report_disputed`, and `dispute_resolved`. The moderator update contains the new moderator list. The other five events include the report id, subject, state, and report body hash; `report_disputed` and `dispute_resolved` also include the dispute id, and `report_moderated` and `dispute_resolved` also include the moderator and the reason hash. `owner_can_set_moderators` proves the sixth event, `moderators_updated`, and its list. `emits_all_five_nep_297_events_with_report_identity` is named for the five report and dispute events and proves their report id, subject, state, body hash and dispute id; no test asserts the moderator and reason hash fields.
