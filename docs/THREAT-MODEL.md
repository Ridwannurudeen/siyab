# Threat model

This model covers the NEAR agent payment path, the MCP and HTTP verdict interfaces, the Gate, registry recording, reports, read-only Intel API, and the OutLayer approver adapter. (gate/agent.py:286-361; mcp/server.py:145-179,181-192,194-206,213-249,251-282; gate/http.py:78-104,155-165,194-244; contracts/gate/src/lib.rs:149-309; contracts/registry/src/lib.rs:123-140,141-151,152-191; contracts/reports/src/lib.rs:273-374,375-444,482-545,546-640,676-687; intel/api.py:229-260,261-276,283-302; gate/outlayer.py:58-88,91-127)

## Assets

| Asset | What is protected | Existing control |
|---|---|---|
| Gate funds | NEAR and FT balances held by the Gate. The owner also has a direct withdrawal method. (contracts/gate/src/lib.rs:293-309; contracts/gate/src/policy.rs:231-245) | Agent transfers require an accepted ALLOW and configured caps. Owner withdrawal checks the owner and one yoctoNEAR. (contracts/gate/src/lib.rs:194-210,212-237,293-309; contracts/gate/src/policy.rs:231-245) |
| Verifier key | The live signer reads and uses the key file named by VERIFIER_KEY_FILE; the Gate verifies the verdict signature and time bounds. (gate/agent.py:71-78; gate/signer.py:29-45,58-76; contracts/gate/src/verdict.rs:53-96) | The owner can rotate the current and previous verifier keys and set the previous key's expiry. (contracts/gate/src/policy.rs:163-182) |
| Recorder authority | The registry's configured recorder can write verdict and label records; the owner can replace that account. (contracts/registry/src/lib.rs:123-140,141-151,152-191,192-205,253-259) | Writes require the recorder account; batch length, verdict ID length, and hash formats are checked. Those checks do not verify a Gate signature. (contracts/registry/src/lib.rs:141-151,152-191,253-259,260-291,293-309) |
| Agent key | The Gate registers an agent public key and gives it a function-call access key scoped to request_transfer. (contracts/gate/src/policy.rs:49-92) | The Gate checks that the signer is a registered, enabled agent and enforces denylist and transfer caps. (contracts/gate/src/lib.rs:168-180,212-237) |
| Label store | The local label store contains assertions, source fields, provenance, and supersession links. (intel/labels.py:37-51,53-61,97-130,161-191) | The loader validates row shape, source format, provenance, hashes, and supersession references. These checks do not establish that a source is truthful. (intel/labels.py:97-130,161-191) |

## Entry points

| Entry point | Exposure and existing boundary |
|---|---|
| Agent pay | Obtains or reads a verdict and submits request_transfer only with a structurally valid signed ALLOW; DENY, UNKNOWN, and unsigned ALLOW are not sent. (gate/agent.py:286-361) |
| MCP server | Exposes payment checks, quote preflight, and account scans; tool dispatch rejects malformed and unknown names, and framed messages over 1,048,576 bytes are refused before reading the body. (mcp/server.py:145-179,181-192,194-206,213-249,251-282) |
| HTTP verdict endpoint | Requires a configured API key and rate limit, returns unsigned verdicts, and passes REPORTS_ACCOUNT_ID to the verdict service when set. (gate/http.py:78-104,155-165,194-244) |
| Intel API | Serves health, feed, issuer, search, account, entity, label, incident, evidence, flow, and cluster reads; static paths are confined beneath the selected site root. (intel/api.py:229-260,261-276,283-302) |
| Gate request_transfer | Checks pause state, caller, registered agent, ALLOW, replay use, and caps before scheduling a NEAR or FT transfer. (contracts/gate/src/lib.rs:149-309) |
| Registry recorder methods | record, record_batch, and record_label are recorder-only; batch length, hashes, verdict ID length, and duplicate label assertion hashes are checked. (contracts/registry/src/lib.rs:123-140,141-151,152-191,253-259,260-291,293-309) |
| Reports contract | Writes are submit_report, moderate, dispute, and resolve_dispute; views include report and dispute reads, subject_summary, version, and state_version. (contracts/reports/src/lib.rs:273-374,375-444,482-545,546-640,641-643,645-647,676-687,248-250,252-254,256-259) |

## Actors and threats

| Actor and threat | Mitigation present | Residual risk |
|---|---|---|
| Prompt-injected agent directs a payment to an attacker. | The injection check scans the transfer memo locally and may send that memo to ShieldBot; the payment path sends only a signed ALLOW. (gate/rules.py:418-440; gate/agent.py:286-361) | The scanner receives the memo, not the agent's full prompt or other context. A clean ALLOW with no visible Gate-policy refusal proceeds without human confirmation. **Open.** (gate/rules.py:418-440; gate/verdict.py:103-109; gate/agent.py:286-361) |
| Malicious payee uses a lookalike or newly controlled account. | Non-allowlisted receivers get age, dust, lookalike, and contract-metadata checks; the Gate enforces per-call and window caps. (gate/rules.py:223-237,457-492,495-541,544-637,640-660,713-730; contracts/gate/src/lib.rs:212-237) | Allowlisted receivers skip tier-two checks. A listed payee that turns malicious or is compromised before it is labelled remains within the configured caps. **Open.** (gate/rules.py:713-730; contracts/gate/src/lib.rs:212-237) |
| Malicious token or receiver contract misrepresents its behavior. | FT checks require a catalog or cap token, sane ft_metadata, receiver storage registration, and any configured issuer blacklist checks. Missing contract source metadata can add a signal only alongside another tier-two signal. (gate/rules.py:298-321,324-395,397-415,544-637,640-660) | These checks do not attest execution behavior. The Gate calls ft_transfer and treats a non-failed promise result as completion; a receiver with contract_source_metadata passes the metadata check without a behavior review. **Open.** (contracts/gate/src/lib.rs:293-309,312-349; gate/rules.py:640-660) |
| Compromised operator machine uses credentials or changes local inputs. | The agent access key is scoped to request_transfer; transfer caps, pause, allowlist, and verifier rotation are owner-controlled. The label loader checks content consistency. (contracts/gate/src/policy.rs:49-92,104-115,139-162,163-182,193-198; contracts/gate/src/lib.rs:168-180,212-237; intel/labels.py:97-130,161-191) | An owner key can withdraw a chosen asset amount to a chosen receiver, up to the Gate balance. Verifier and agent credentials together can submit transfers within Gate policy. A host writer can recompute label hashes, which do not authenticate source truth. **Open.** (contracts/gate/src/policy.rs:231-245; gate/signer.py:29-45,58-76; gate/agent.py:65-70,286-361; contracts/gate/src/lib.rs:194-210,212-237; intel/labels.py:53-61,161-191) |
| Compromised recorder writes false registry data, including an unsigned ALLOW. | Only the configured recorder can write; batch length, hash format, and label assertion-hash reuse are checked. (contracts/registry/src/lib.rs:123-140,141-151,152-191,253-259,260-291,293-309) | RecordInput has no signature field, record_one stores the supplied verdict without signature or evidence verification, and is_allowed accepts a stored ALLOW. record_label stores caller-supplied fields with a parsed assertion hash without recomputing that hash from the fields. **Open. Medium.** (contracts/registry/src/lib.rs:20-26,152-191,210-223,260-291,293-309) |
| Spam reporter floods reports across multiple submitters. | Reports and disputes require the exact REPORT_DEPOSIT; each submitter is limited to five pending reports. (contracts/reports/src/lib.rs:9,273-374,482-545,715-721) | The pending limit is per submitter, not global, so many submitters can create reports in parallel. **Open. Medium.** (contracts/reports/src/lib.rs:273-374) |
| A single moderator holds all moderation power. | The owner configures a distinct moderator list; moderators can moderate reports and resolve disputes. With multiple moderators, the moderator who accepted a report cannot resolve its dispute. (contracts/reports/src/lib.rs:261-272,375-444,546-640,807-812) | With one configured moderator, that moderator can accept a report and resolve its dispute. There is no independent reviewer in that configuration. **Open. Medium.** (contracts/reports/src/lib.rs:546-640,1847-1876) |
| A signed ALLOW carries action ask. | The verdict service defaults to signing only action sign, and ordinary pay refuses an ask. The attack harness deliberately requests sign and ask to exercise Gate policy refusals. **Mitigated in ordinary payment. Low.** (gate/verdict.py:61-63,103-109; gate/agent.py:228-234,286-361,386-434) | The verifier is still trusted to sign; the Gate must enforce the visible policy itself. (contracts/gate/src/lib.rs:149-210,212-237) |
| The configured reports contract read fails or is unreachable. | When REPORTS_ACCOUNT_ID is set, a denied report signals DENY, unreadable or malformed summaries become UNKNOWN, and only ALLOW is signed. The HTTP endpoint now passes this setting through. (gate/http.py:78-104,155-165; gate/rules.py:324-395,676-710; intel/reports.py:5-31,34-54; gate/verdict.py:103-109) | An unavailable summary prevents an ALLOW signature. Unsetting REPORTS_ACCOUNT_ID skips this check. **Open. Medium.** (gate/rules.py:324-395; gate/http.py:78-104) |
| Caller floods the read-only Intel API. | Static path resolution rejects targets outside the configured site root. (intel/api.py:261-276) | The GET handler has no authentication or request-rate control, so availability under abusive read traffic is **open**. (intel/api.py:283-302) |
| An OutLayer approval's request_data describes another operation than the one its request_hash covers, and an approver signs the adapter's vote over that hash. | The OutLayer voter adapter judges only a pending NEAR transfer or ft_transfer call in which it reads every field except a call's gas, which it accepts unjudged, abstains on every other operation and on action ask, and signs nothing, sends nothing and reads no key; it returns the vote message for the approver's own key to sign. (gate/outlayer.py:58-88,91-127; docs/OUTLAYER.md:36-53) | The vote message carries the approval's request_hash as given, checked only as a non-empty string: the adapter judges request_data and does not recompute request_hash, because OutLayer does not specify the canonical JSON form it hashes, so an approval whose request_data and request_hash disagree gets a vote on an operation the verdict did not judge. The approver's key signs the vote outside this repository, so its custody is outside this model. Nothing has run against OutLayer. **Open. Medium.** (gate/outlayer.py:91-127; docs/OUTLAYER.md:53,62,66) |
| A 1Click quote verdict is applied to a quote it did not judge: a tampered or stale quote answer, or a later quote whose request differs. | Every quote request is dry; the answer must echo the five bound request fields as sent, or quote_dry is a signal; the evidence document records them with the quote's correlationId, timestamp, amountOut and minAmountOut; verify_binding refuses an answer whose evidence hash, kind, verdict or bound fields do not match a later quote request. (gate/intents.py:81,118-124,126-137,180-195,197-264,265-285; docs/API.md:207-209) | The answer is unsigned, so verify_binding does not refuse an answer forged whole with its hash recomputed, and the 1Click answer's own signature is not verified, since no 1Click verifying key is recorded. Nothing in the repository but the tests calls verify_binding yet, so the binding holds only for a consumer that calls it. It sets no age bound: the quote's timestamp is recorded, but verify_binding reads neither it nor the document's observed time, so an old answer still verifies against a later quote request with the same five fields. It compares the request, not the later quote's deposit address. **Open. Medium.** (gate/intents.py:197-264,265-285; tests/test_intents.py:1-3,177-180,181-190,191-201,202-209; tests/test_mcp.py:120-122; docs/API.md:209-210) |

## Closed on main

| Closed threat | Fix on main |
|---|---|
| A report submitter moderates their own report; duplicate moderators or same-moderator review bypass distinct review. | moderate rejects the report submitter, moderator configuration rejects duplicate accounts, and the moderator who accepted a decision cannot resolve its dispute when more than one moderator is configured. (contracts/reports/src/lib.rs:261-272,375-444,546-640,807-812) |
| Reports or disputes accept a non-exact deposit. | Both write paths call the shared check, which requires attached deposit to equal REPORT_DEPOSIT. (contracts/reports/src/lib.rs:9,273-374,482-545,715-721) |
| Pending reports change a payment verdict. | A pending-only summary has no effect; the configured verdict path uses that summary. (intel/reports.py:34-54; gate/rules.py:324-395) |
| A DENY can cite a newer social report instead of the deny report. | subject_summary exposes latest_deny_id and the reports effect uses that field for DENY. (contracts/reports/src/lib.rs:676-687,761-771; intel/reports.py:34-45) |
| Repeated upheld disputes exhaust a report's lifetime dispute cap. | Reports 0.1.2 removes the lifetime cap and checks only the last dispute to prevent a second concurrently open dispute; the regression test permits an eighth dispute after seven non-overturning resolutions. Testnet runs deployed Reports version `0.1.2` since the 7 Nov redeploy. (`contracts/reports/Cargo.toml:3`; `contracts/reports/src/lib.rs:482-545,1733-1757`; `res/BUILD-reports.md:5,7`; `docs/TESTNET.md:36`; `docs/spec/report-v1.md:48,58) |
| Used-verdict storage grew without automatic pruning, and a verdict could be issued far in the future. | Source version 0.2.0 prunes up to four expired used verdicts per request, stops at a live queue head, and rejects issued_ms more than 30,000 ms ahead. Testnet runs Gate 0.2.1 since 7 Nov (`res/BUILD-gate.md`). (contracts/gate/Cargo.toml:3; contracts/gate/src/lib.rs:65-93,149-158; contracts/gate/src/verdict.rs:53-96; res/BUILD-gate.md:5,7; docs/TESTNET.md:32) |
| The HTTP verdict endpoint skipped the configured reports check. | The endpoint reads REPORTS_ACCOUNT_ID at startup and passes it to the verdict request. When set, the rules include the community report check. (gate/http.py:78-104,155-165; gate/rules.py:324-395) |
