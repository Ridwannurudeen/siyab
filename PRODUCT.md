# Siyab

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

People investigating NEAR accounts and entities, and teams checking agent payment destinations. The owner confirmed that investigation is the primary website experience, with payment and access-key checks easy to reach.

## Product Purpose

Connect account identity, observed activity, recorded relationships and underlying evidence. Support payment destination checks and independent verification of recorded verdicts.

## Positioning

Every label names its source and every verdict has evidence. The browser reads mainnet data without signing. The demonstrated Gate and registry run on testnet.

## Operating Context

The site is generated by a standard-library Python renderer with vanilla browser JavaScript. It is hosted on the existing VPS. Offline fixtures and recorded investigations remain useful when live providers are unavailable.

## Capabilities and Constraints

- Searchable sourced labels, registry entities and linked account pages.
- Mainnet payment, access-key and intent destination reads.
- A current feed with freshness and coverage metadata; the public response contains at most 50 recent events.
- Recorded fund-flow and relationship datasets with explicit scope and provenance.
- Aggregate results for a recorded receiver cohort; individual judgement identities are not published by that view.
- Independent testnet registry reads and evidence-hash comparison.
- Browser investigations, view settings, notes, watchlists and optional desktop alerts remain available without signing in. Browser storage is the default save destination; JSON import/export moves that local work explicitly.
- With external state configured, authenticated team workspaces retain shared investigations, versioned notes, recipient-bound invitations, roles, watchlists, inbox acknowledgements and application audit entries. Signing in never uploads browser work; shared saves and imports require an explicit choice.
- Separate background workers retain matching feed evidence and poll watched accounts for ordinary transfers while browsers are closed. Their heartbeats, retry queues and coverage gaps are separate. Delivery is to the team inbox; email and external notification delivery are not configured.
- Arbitrary mainnet accounts can be investigated through sourced profile, holdings, transaction and transfer reads, bounded live flow/relationship graphs, durable observations and resumable provider-page backfills. Provider windows and polling caps do not establish complete account history or complete missed-event recovery.
- Contract code, validator observations, token metadata and contract-reported source metadata expose their read sources. A reported token name, source link or standard does not establish ownership, verified source code or a risk verdict.
- Table CSV, scoped graph JSON and workspace backups preserve their distinct sources and limits. No universal wallet portfolio or price history is established by this repository. Operational setup and bounds are in [docs/WORKSPACES.md](docs/WORKSPACES.md).
- Historical data, attribution hypotheses, incomplete coverage, unavailable values and network boundaries must remain explicit.
- Historical evidence, deployed protocol identifiers and existing GitHub evidence URLs remain unchanged by visual work.

## Brand Commitments

The owner selected Siyab as the independent product name and an investigation workspace as the first screen. The approved visual direction is a dark navy and teal analytics application: persistent desktop navigation, a compact context header, aligned chart and table panels, and evidence beside the investigation. Interface text and numeric data have distinct self-hosted type roles. The work should be deliberate and simple, with motion in appropriate places. Existing content, functions and motion must be preserved; removal requires separate explicit approval.

## Evidence on Hand

The repository contains sourced labels and entities, incident pages, recorded flow and cluster datasets, a recorded receiver judgement cohort, testnet records and verification fixtures. Live feed state is external to the repository. The reference study and screenshots are in the sibling handoff directory under `near-hackathon-2026-11/design/`.

## Product Principles

- Evidence stays adjacent to the conclusion it supports.
- Rich views expose real data and their bounds.
- Search, selection and detail views form one investigation path.
- Unavailable data remains unavailable rather than becoming a favorable result.
- Preserve existing functions and make the phone layout usable.

## Accessibility & Inclusion

Keyboard operation, visible focus, readable contrast, reduced-motion support and layouts that reflow without page-wide horizontal scrolling are required. Interactive graphs retain accessible textual evidence and controls.
